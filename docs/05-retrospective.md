# 复盘

本文件由Codex依据实际实现和评审意见（含 Claude 评审）辅助起草。个人问题发现与方案贡献已记录在 [04-ai-usage.md](04-ai-usage.md)。
## 最难的问题

最初把事实安全等同于逐句白名单，导致“支持字幕”之外的叙事都被拒绝。虽然工具通过、模型能结束，1.5秒结果却没有满足创作者对完整脚本的需求；仅检查时长上限进一步掩盖了这个问题。

根据评审意见，我决定改为产品声明严格核验，其他叙事扫描风险信号，并给30秒目标设置20–30秒区间。这样可以创作场景、转场和互动，而不用编造更多产品事实。代价是词法检查仍有漏检和误报，不能夸大为语义事实保证。

## 决策证据的改进

旧超时用例在输入指定三个分镜、目标只有3秒，并靠结束门禁促成修改，不能代表自然调整。本版普通30秒请求实际出现15.3→30.4→28.6秒，模型先充实、再压缩，并重新检查，过程中没有GUARD_REJECTED。

这条记录来自保留全部结果的有限采样，不是一次稳定成功的证明。其他尝试出现了偏短后索要资料、版本遗漏、过长或过短后结束，均保留并说明。错误恢复和无素材改写也有独立真实路径。

## 工程收获与取舍

- 业务成功标准要包含可用内容，不能仅把格式与检查通过当作完成目标。
- 来源存在不等于支持整段文字，合法引用之外的额外宣传也要检查。
- 修改时应该用清晰状态反馈告诉模型还缺什么检查，比模糊报错有效。
- Mock只验证流程。真实运行才能暴露模型在判断、参数和上下文上的问题。
- 拆分RunState、参数契约和提示词汇有利于阅读与解释模型/程序职责。
- 模型支持推理参数不等于所有API与工具组合都支持；实际Chat400促使改用Responses，并保留原始服务上下文。

## 下一步

改进字幕/旁白节奏及可拍性盲评；扩充有来源的产品素材；评估隐含声明与同义改写的核验；固定测试集重复测量事实错误、有效修正、工具成本和任务成功率；使用真实配音校准估时。不能通过增加装饰界面替代这些核心改进。
