# 短视频脚本 Agent：需求与验收基线

## 用户与目标

面向需要介绍产品的短视频创作者。用户提供主题、受众、平台、目标时长和风格，Agent 使用给定的产品资料和品牌规则，生成有事实依据、可编辑且满足时长约束的脚本。

成功的核心是事实可追溯与约束得到实际验证，不以文案华丽程度、界面或框架名称衡量。

## 范围与实现选择

- 采用 Python CLI、本地 JSON 素材与品牌规则、原生模型工具调用循环。
- 必须提供素材检索、时长估算、规则检查三个工具。
- 模型根据工具返回结果选择后续动作；程序负责参数验证、执行工具、维护状态及执行上限。
- 提供真实模型与离线 Mock 两个入口。Mock 仅验证流程，不能证明真实模型的动态决策效果。
- 本阶段不包含界面、线上部署、多 Agent、音视频生成和生产级运行环境。
- 交付文本脚本；估算时长不等于实际配音或剪辑时长。

## 输入契约

机器格式见 `../schemas/input.schema.json`，完整示例见 `../examples/inputs/normal.json`。

| 字段 | 说明 | 缺失处理 |
| --- | --- | --- |
| topic | 主题或需要介绍的功能 | 请求补充 |
| audience | 目标受众 | 请求补充 |
| platform | 发布平台 | 请求补充 |
| target_duration_seconds | 目标时长，正数，单位秒 | 请求补充 |
| style | 文案风格 | 请求补充 |

以上五项均为当前最小产品的业务必填项，不擅自填写默认值。输入 schema 允许字段缺失或为 null，以便系统接收不完整请求；缺失、null、空白字符串都属于信息不足。非法类型、未知字段、非正时长属于输入格式错误，由 CLI 拒绝并显示字段错误，不启动 Agent。

产品素材和品牌规则由本地 `data/` 目录提供，不要求用户在每次请求中重复输入。自然语言字段视为业务数据，不得覆盖工具权限、品牌规则或执行上限。

## 输出契约

机器格式见 `../schemas/output.schema.json`。每次任务输出以下字段：

| 字段 | 说明 |
| --- | --- |
| status | 任务状态，见下表 |
| message | 给用户的简短结果或未完成原因 |
| missing_fields | 缺少的业务输入字段 |
| questions | 需要用户补充的信息或素材问题 |
| script | 脚本对象；无法形成草稿时为 null |
| checks | 针对当前脚本版本的时长、事实、品牌检查 |
| risks | 未解决风险或估算限制 |
| tool_calls_used | 实际工具调用次数 |

脚本包含 `version`、`title`、`scenes`、`estimated_total_duration_seconds`。每个分镜包含唯一 `id`、画面说明 `visual`、旁白 `voiceover`、字幕 `subtitle`、估算时长 `estimated_duration_seconds`、产品事实声明 `claims`。旁白和字幕至少一项非空。

每条产品事实声明包含脚本中的原文 `text`、素材 `source_id` 和事实 `fact_id`。所有产品能力、性能、数字、效果承诺及产品画面暗示均必须受资料支持；标题也属于检查范围。纯粹的叙事连接语无需伪造来源。全片来源列表可从各分镜的 claims 去重得到。

### 状态定义

| 状态 | 使用条件 |
| --- | --- |
| completed | 最终脚本版本通过时长、事实及品牌检查，且业务输入完整 |
| needs_input | 缺少业务信息，或模型决定请求用户补充资料；必须有具体 questions |
| insufficient_material | 当前材料不足以支持请求，未输出可交付脚本，并说明资料缺口 |
| tool_error | 工具或模型服务失败，且无法继续完成；不得伪装为检查通过 |
| constraints_unsatisfied | 无法同时满足时长、事实或品牌约束，说明未满足项 |
| step_limit_reached | 达到执行上限仍未完成；输出未完成原因和已有检查结果 |

失败状态可保留草稿，但不得把草稿描述为已验收结果。

### 必须由程序维护的约束

1. 最多 10 次工具调用、12 轮模型决策；两者任一耗尽且任务未完成时返回 `step_limit_reached`。无效工具请求也占用一次模型决策轮次，防止无限循环。服务请求另设超时，具体实现值在运行文档中说明。
2. 修改脚本必须递增版本号，并使旧版检查失效。模型不得自行宣称检查通过；检查状态、估时和调用计数来自程序执行结果。
3. `completed` 要求三类检查均为 passed，且 `checks.script_version == script.version`。缺失或未运行的检查不能视为通过。
4. 总时长等于逐分镜估算时长之和；总时长不得超过用户目标。时长计算采用统一精度，具体算法在工具实现阶段记录。
5. 旁白和字幕同时呈现时不得重复累计朗读时间；停顿、纯画面等时长须有明确估算规则。
6. 每个 claim 引用的素材、事实都必须存在，且事实确实支持该表述。仅验证 ID 存在不足以证明事实正确。
7. 字幕、画面、旁白、标题均不得暗示资料未提供的产品功能。自动规则检查的语义覆盖有限，真实运行材料还需人工逐项审阅并记录结果。

## 合成资料与品牌规则

`../data/materials.json` 是为本考核编写的合成资料，不是任何真实产品的公开声明。P01 仅允许陈述“支持字幕”。不得从中推断自动生成字幕、识别准确率、多语言、翻译、操作步骤、处理速度或效率提升等事实。

`../data/brand_rules.json` 固定检查规则与风险边界。工具必须返回可定位的违规说明，例如分镜 ID、问题文本、规则 ID，而非仅返回 true/false。

## 动态决策与运行记录

至少实现一次“模型选择动作 → 工具执行 → 模型观察 → 调整动作或结束”的实际循环。检索无结果时，是否改写查询或请求补充由模型选择；估时或规则不通过时，是否修改并再次检查或说明失败也由模型选择。

Trace 保存步骤编号、脚本版本（如适用）、动作、工具参数、返回摘要、后续动作和简短决策依据，不保存模型内部思维过程，不保存密钥。至少两条真实模型运行路径必须显示不同工具反馈引发不同后续行动。

## 验收清单

以下是端到端验收计划，现已完成五类真实模型用例及离线边界测试，实际范围见 `03-evaluation.md`。后续每组用例应保存 input.json、output.json、trace.jsonl，并由评估文档引用实际文件。

| ID | 场景与输入变化 | 通过条件 |
| --- | --- | --- |
| A01 | 正常：完整输入，P01 可检索 | 输出标题、分镜、来源、风险、总时长；三项检查通过且绑定最终版本；不扩写产品事实 |
| A02 | 信息不足：删除 target_duration_seconds | 返回 needs_input，明确请求目标时长，不擅自填值 |
| A03 | 无素材：配置检索始终返回空 | Trace 显示模型观察空结果并决定改写查询、请求补充或结束；终态为 needs_input 或 insufficient_material，不编造素材 |
| A04 | 工具失败：注入结构化工具错误 | 错误进入模型观察，模型决定重试或结束；恢复后才能 completed，未恢复返回明确未完成状态 |
| A05 | 超时修正：首稿实际估时超限 | 模型依据超时结果改稿并重新估时、检查；成功则最终时长达标，否则明确失败；不得手写虚构的估时记录 |
| A06 | 执行上限：持续不满足约束 | 最多 10 次工具调用或 12 轮模型决策后返回 step_limit_reached，不无限重试 |
| A07 | 对照：仅改变目标时长或检索结果 | 保存两次实际运行，比较模型是否据反馈调整动作；固定脚本或预设决策日志不能充当证据 |
| A08 | 无依据事实：草稿包含“效率提升 80%”或“自动生成字幕” | 规则/事实检查指出违规位置和来源不足，不允许未经修正标记 completed |
| A09 | 检查版本：通过检查后修改脚本 | 旧检查失效；未对新版本重新检查不得 completed |

A01–A05 覆盖题目必验场景。A06、A08、A09 可先做离线工程测试；A07 需真实模型对照运行。Mock 与真实模型结果分别标注，若模型不可用，明确记录真实决策证据尚未完成。

- 验收条件包含题目全部必验场景、真实动态决策证据及调用上限。
- 第一步仅定义契约；第三步已实现 Agent、CLI 和离线 Mock 测试，五类真实模型单次验收已完成，稳定性和文案质量仍有限制，详见评估。
