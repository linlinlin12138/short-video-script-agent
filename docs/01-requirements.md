# 需求与验收标准

## 用户和目标

用户是需要介绍产品的短视频创作者。他们给出主题、受众、平台、目标时长和风格，希望拿到一份能直接拍、也能自己再改的脚本。

一份合格的脚本要同时满足三点：

1. **内容完整**：有开场、分镜和收尾，能看出是写给谁、发在哪个平台的。只有一句“支持字幕”不算 30 秒脚本。
2. **事实可追溯**：每条关于产品的说法都能对应到素材里的具体事实，不能编造功能或效果。
3. **时长合适**：预计时长落在目标的三分之二到目标之间（30 秒对应 20–30 秒）。

不做的部分：界面、线上部署、多 Agent、音视频生成。

## 输入

字段见 [input.schema.json](../schemas/input.schema.json)：`topic`、`audience`、`platform`、`target_duration_seconds`、`style`。

五项都是必填。缺字段、值为 null 或空字符串时，程序照常接收，由 Agent 向用户提问；类型错误、出现未知字段、时长不是正数时，CLI 直接报错，不启动 Agent。

产品素材和品牌规则放在 `data/`，用户不需要每次提供。素材是合成的，P01 只有一条事实：“支持字幕”（P01-F1）。

## 输出

字段见 [output.schema.json](../schemas/output.schema.json)：

| 字段 | 内容 |
| --- | --- |
| status | 任务状态，见下表 |
| message | 结果说明或未完成原因 |
| missing_fields / questions | 缺少的字段，以及给用户的中文问题 |
| script | 标题、版本、分镜、总时长；每个分镜有画面、旁白、字幕、预计时长和 claims |
| source_ids | 脚本引用的素材 ID，去重 |
| checks | 当前版本的时长、事实、品牌、语义复核结果和具体问题 |
| risks | 仍然存在的风险 |
| tool_calls_used | 实际调用工具的次数 |

每条 claim 记录脚本中的原文、`source_id` 和 `fact_id`。

| 状态 | 含义 |
| --- | --- |
| completed | 当前版本全部检查通过 |
| needs_input | 缺业务信息或需要补充资料，附具体问题 |
| insufficient_material | 素材支撑不了这个主题 |
| tool_error | 工具或模型服务出错，无法继续 |
| constraints_unsatisfied | 改过之后仍不能同时满足时长和事实要求 |
| step_limit_reached | 达到工具调用或模型轮数上限 |

没完成的任务可以带上已经估过时长的草稿，但不能标成可交付。

## 事实规则

- 产品声明必须逐字对应素材事实，引用的素材和事实 ID 必须存在，并且出现在引用它的那个分镜里。
- 开场提问、创作者的经历、拍摄建议、互动收尾这类不涉及产品的内容可以自由写，不需要引用。
- 引用了“支持字幕”，不代表可以写“自动生成字幕”“效率提升 80%”。
- 标题、画面、旁白、字幕都在检查范围内。画面里也不能出现素材没有提到的产品界面或操作步骤。

## 完成条件

Agent 只有在以下条件都满足时才能结束为 `completed`：

- 五项输入齐全；
- 当前版本的脚本通过时长、事实、品牌和语义复核；
- 引用的事实来自本次运行实际检索到的结果；
- 检查结果对应的正是最终这一版脚本（改了内容就要升版本号，旧的检查结果作废）。

工具调用最多 10 次，模型决策最多 12 轮，用完时返回 `step_limit_reached`。

## 验收用例

| ID | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | 正常生成 | 普通 30 秒请求，得到 20–30 秒、多分镜、引用 P01 的脚本，检查全部通过 |
| A02 | 缺信息 | 去掉目标时长，Agent 用中文问句询问，而不是只返回字段名 |
| A03 | 无素材 | 检索不到时，由模型决定换个查询或请求补充，不编造资料 |
| A04 | 工具失败 | 错误信息交给模型，由模型决定重试或结束；恢复后要重新检查 |
| A05 | 超时修正 | 普通 30 秒请求，输入不暗示怎么改；估时超长后模型自己修改并重新估时 |
| A06 | 上限 | 用完预算时停止，并返回未完成状态 |
| A07 | 动态决策 | 至少两条真实记录能看出模型根据不同的工具结果选择了不同的下一步 |
| A08 | 事实 | 允许不涉及产品的叙事；拦住没有依据的能力和效果声明 |
| A09 | 版本 | 修改后旧检查失效，最终输出的时长与检查结果一致 |

每个用例保存输入、输出和 Trace。Trace 记录每一步的工具、参数、返回结果、一句话决策依据和下一步动作，不记录模型的内部推理。实际结果见 [评估报告](03-evaluation.md)。
