# 方案设计（第三步：Agent 循环）

## 当前实现

采用 Python 3.10+ 标准库，无 Agent 框架及额外依赖。工具实现位于 `src/tools/local.py`，统一通过 `ToolSet.execute(name, arguments)` 调用。

成功封装为 `{ok: true, tool, result}`；失败封装为 `{ok: false, tool, error: {code, message, retryable}}`。空检索和检查不通过是成功执行得到的业务结果，不是工具错误。retryable 仅提供错误属性，工具不会自动重试，也不会替模型决定下一步。

工具接收脚本草稿：version、title、scenes 必填，每镜包含 id、visual、voiceover、subtitle、claims。模型填写的估时字段不作为计算依据。最终输出仍须满足 `schemas/output.schema.json`，由后续 Agent 编排层组装。

## 素材检索

`search_materials(query, limit=5)` 对查询和 ID、标题、关键词进行去标点、去空白、大小写归一化，再用双向子串匹配计分。按得分降序、ID 升序返回命中资料，保留原始事实。

适用于当前一条合成素材，结果可复现。无向量检索或同义词理解；“视频降噪”返回空。长查询包含“字幕”时可能命中 P01，这不代表资料支持长查询中的其他功能，必须由后续事实检查限制。

## 时长估算

`estimate_duration(script, target_duration_seconds)`：

- 一个汉字计一个单位；一个连续英文字母单词计一个单位；每个数字计一个单位；其他文字字符逐字符计数，标点空白不计数。
- 每镜时长 = max(旁白单位数 / 4，字幕单位数 / 5，1 秒画面下限) + 0.5 秒停顿。
- 每镜向上取一位小数，再用 Decimal 求和，避免浮点误差或向下舍入导致误判达标。
- 旁白与字幕同时呈现，取较长者，不相加。超限时返回 failed 和 over_by_seconds。

该规则是启发式阅读/配音估算，不能保证真实成片时长；当前不支持用户单独指定动作、长停顿等复杂时间线。

## 事实与品牌检查

`check_rules(script)` 同时检查标题和所有分镜画面、旁白、字幕：

1. 引用素材和事实必须存在；claim 原文需与素材事实一致，且出现在所属分镜中。
2. 按句末标点拆分句段，只接受素材事实原文或配置中的完整中性表达。未知句段返回 BR01，表示未得到支持，不宣称该句已被证明为假。
3. 每个含事实的分镜都需要本镜的有效引用；标题含事实时，至少一个分镜须提供对应引用。
4. 品牌规则示例匹配提供可定位的问题；未知扩写即使未命中示例，也会被受控表达检查拦截。

选择保守检查是为了让最小合成资料场景中的完成状态有明确依据。代价是自由文案、同义改写和混合长句容易被拒绝，需要按已支持句段改写。这不是通用语义事实检查器。后续真实模型运行还需人工核对输出。

## 版本与故障

估时与规则检查均返回 script_version 和输入脚本规范化 JSON 的 SHA-256 script_hash。即使模型忘记递增版本，正文变化也会改变哈希；编排层据此拒绝复用旧结果。编排层已实现完成门禁，版本或草稿内容变化时清空旧检查，拒绝修改正文却不递增版本号。

`ToolSet(failures={"search_materials": 1})` 可注入一次可重试错误，仅用于测试；之后恢复正常。数据文件缺失、损坏或结构无效返回 DATA_UNAVAILABLE，不返回空素材或检查通过。

## 动态决策

已接入 src/agent.py：模型每轮选择 search_materials、estimate_duration、check_rules 或 finish，观察工具结果后再次决定。程序不代替真实模型选择查询和修正策略。每次工具结果、参数、公开决策依据和下一动作都写入 Trace；不存模型内部思维过程。

src/models.py 的 HTTPModel 按 Chat Completions 函数调用格式工作，串行单动作，回传 tool 消息；请求不使用模型专属参数。要求选定模型支持该协议，不保证所有模型兼容。协议参考 [OpenAI 官方函数调用文档](https://developers.openai.com/api/docs/guides/function-calling)。已使用用户配置的官方 API 和 gpt-5.4-mini-2026-03-17 完成五类真实运行。函数定义启用 strict，所有对象字段显式必填并禁止未知字段；脚本的非空旁白/字幕由程序校验。

默认 10 次工具调用、12 轮模型决策，单次 HTTP 超时 45 秒。无效动作也消耗轮数；工具失败可以被模型观察。程序拒绝擅自改变目标时长，最终完成要求输入完整、当前草稿两工具检查通过，且产品声明引用来自本次检索。估时结果由程序填入最终分镜和总时长。

MockModel 是基于观察结果的固定模拟器，修改策略和文案预设，不算 ReAct 达标证据。正常、缺信息、无素材、失败恢复、超时修正、上限六组离线记录位于 examples/mock/。真实模型不同决策路径及问题修复记录见 examples/live/README.md。


## 真实验收后的修正

- 明确提供缺失字段，避免模型漏问目标时长或额外索要已有本地资料。
- 为每个动作提供用途说明，明确一条事实可组成最小脚本；按严格 schema 约束单动作参数。
- 明确受控表达边界，避免自由加前缀导致检查失败。
- 对尚未尝试修正的超时草稿，若目标至少 1.5 秒（当前工具单镜下限），拒绝直接宣称无法满足。程序回传 GUARD_REJECTED，模型自主选择如何改稿；不自动生成修正版。
- CLI 增加 --env-file，仅读取三个模型配置项作为文本，不执行配置内容；不在记录中保存密钥。

结束门禁的 1.5 秒下限依赖当前估时规则，修改估时算法时必须同步更新此约束及测试。
