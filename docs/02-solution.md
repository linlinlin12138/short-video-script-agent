# 方案与取舍

## 代码职责

| 文件 | 职责 |
| --- | --- |
| src/agent.py | RunState 管理草稿/检查/来源，Agent 执行有上限的模型工具循环 |
| src/contracts.py | 输入、动作、finish 参数、自然语言问句及工具 schema |
| src/prompts.py | 版本化业务指令：受众/平台/风格、叙事边界、时长和错误含义 |
| src/models.py | Responses / Chat Completions 接入与离线 Mock |
| src/tools/local.py | 检索、独立估时、声明与风险信号检查，调用语义复核 |
| src/verifier.py | 产品声明语义复核：逐句交给判定模型，程序校验判定结果 |
| src/cli.py | 配置加载、命令行、结果与 Trace 保存 |

原生 Python、标准库实现，无 Agent 框架。循环骨架固定，查询、起草、修改、重试和结束动作由模型选择。程序校验完成条件，不自动改稿，也不伪造修正日志。

## 工具协议与检索

成功为 {ok:true,tool,result}，错误为 {ok:false,tool,error:{code,message,retryable}}。空检索、检查不通过是正常业务结果。retryable=true 表示可能是暂时错误，模型可以重试，不是工具自动重试。观察还附 current_state，告诉模型当前版本缺少哪些检查，避免错用旧版结果。

检索按归一化查询与素材 ID、标题、关键词双向子串计分，按得分及 ID 排序。适用于小规模合成资料，无语义检索。命中资料不意味着其能支持查询中的所有能力。

## 事实与自由叙事

旧版把未知句段全部拒绝，导致模型只能写1.5秒事实卡片。本版取消中性句段白名单：

1. 验证每个 claim 的来源、事实 ID、原文和所属分镜出现位置；原文必须对应资料事实。
2. 按位置扫描标题、画面、旁白和字幕，将本位置被有效引用覆盖的事实原文移出待检文字；标题允许引用分镜中的事实。
3. 扫描余下文字的能力、效果、数字、比较、绝对化及无依据界面信号，同时匹配品牌禁止示例。命中要求证据或改写，不允许拿“支持字幕”的引用替自动翻译背书。
4. 非产品事实叙事自由创作，无信号命中不会因为缺少逐字白名单而被拒绝。

规则2.2按实际漏检补充时间效果（减半/翻倍/耗时）、功能细节（同步/对齐/批量/样式/模板）、中文数量及爆款等效果信号。能/可以/会/帮你/不再按产品或字幕主语上下文扫描，保留一般创作建议。固定10句对抗输入及6条正常叙事均有可执行回归和实际输出，详见评估报告。换一批未参与调词的句子后，词法层留出集只拦住1/12、误拦5/6（见评估报告），说明继续扩词表不可行，因此增加下面的语义复核层。

否定声明不能用肯定事实背书。规则配置见 data/brand_rules.json。

## 产品声明语义复核

check_rules 在词法层之后调用判定模型（src/verifier.py）：

1. 把标题、画面、旁白、字幕逐句拆分，连同素材事实一起交给判定模型，要求以严格 JSON Schema 返回每句中的全部产品声明及 supported/unsupported 判定。判定提示词定义了什么算产品声明（能力、操作、选项、效果、适用性、比较，含隐含表达），以及“支持某功能”不等于该功能如何实现或带来什么效果。提示词示例刻意不使用评估集句子。
2. 程序不直接采信判定：每句必须恰好返回一次，否则视为判定失败；supported 必须给出真实存在的 fact_id（SEM02），且该事实必须在本分镜 claims 中引用（SEM03）；unsupported 记为 SEM01。
3. 判定模型调用失败或返回无效 JSON 时，check_rules 返回 JUDGE_UNAVAILABLE（retryable=true），由 Agent 模型决定重试或结束，绝不当作通过。
4. 配置判定模型后，词法“风险信号”（BR01S）只作为 signals 提示，是否构成问题由语义复核决定，以免“我习惯先把文案同步到备忘录”这类叙事被误拦；品牌禁止示例、引用完整性、逐字核对和否定检查仍直接拦截。未配置判定模型时风险信号照旧拦截，且 Agent 完成门禁要求语义复核 passed，因此没有判定模型不能 completed。

live 模式默认用 OPENAI_MODEL 作判定模型，可用 OPENAI_JUDGE_MODEL 单独指定；每次 check_rules 多一次模型调用，不占 Agent 的工具预算。Mock 模式使用 OfflineJudge 固定标注，只验证流程，不代表语义判定能力。判定模型本身会误判，复核结果不等于事实证明，发布前仍需人工核对。

## 时长与版本

每个汉字计一个单位、连续英文字母单词计一个单位、每个数字计一个单位，其他文字逐字符，标点空白不计。每镜时长为 max(旁白单位/4,字幕单位/5,1秒画面下限)+0.5秒停顿，向上取一位小数后用 Decimal 求和。旁白与字幕同时发生，取较大值。

时长须在目标的三分之二至目标之间；30秒对应20–30秒，避免一句事实也通过。估算不是配音或成片时长；纯动作长停顿暂不支持。

估时和规则结果绑定版本及规范化草稿 SHA-256，修改后清空旧检查；最终程序验证哈希并填入各镜时长与总时长。完成还要求引用出自本轮检索，source_ids 从最终分镜去重。

## 模型接入与记录

默认 Responses，支持 --api chat 兼容接口；strict schema、每轮一个函数动作。Responses 保留服务返回的完整输出项，在下一轮回传真实 function_call_output；加密上下文仅在内存和同一服务间传递，不写入 Trace，不输出内部推理。

真实实验使用 gpt-5.4-mini-2026-03-17。该模型实际返回错误：Chat Completions 不能同时使用函数工具与 low 推理配置，因此新增 Responses 适配。--reasoning-effort 仅应对支持此参数的模型使用。参考 [官方函数调用](https://developers.openai.com/api/docs/guides/function-calling)及[推理上下文说明](https://developers.openai.com/api/docs/guides/reasoning)。

最多10次工具调用、12轮模型决策；无效动作也占轮数。finish 门禁拒绝未检查、问句仅为键名、擅自改目标和过早宣称无法满足等情况。保留门禁并不意味着可据此宣称模型自主修正；验收报告单独标注是否触发过门禁。

Trace 记录模式、模型、API、推理配置、提示版本/哈希、规则版本及实际动作反馈，不含密钥。Mock 文案与修正策略预设，仅验证流程。
